Findings

01 AGENTS.md / CLAUDE.md 🚀 Ship-Ready
CLAUDE.md:1 — opens with "agent operating contract", covers project shape, where-things-go table, feedback loop, testing rules, idioms, panic policy, sidecar schema, prompt-injection defense, config/secrets. Minor: the "Out of scope" section (line 170) lists OCR, MCP, search as stubbed — but mcp.rs, ocr.rs and M3 tests already exist. That's docs drift, flagged separately under item 10.
02 Strict types / compiler settings 🚀 Ship-Ready
Cargo.toml declares [workspace.lints.clippy] pedantic = "warn" plus unwrap_used, expect_used, todo, print_stdout, dbg_macro all warned, and unsafe_code = "forbid". just lint runs clippy ... -D warnings. Currently compiles clean on the workspace.
03 Strict linter / formatter 🚀 Ship-Ready
rustfmt.toml pins edition 2024 + max_width 100; just fmt-check + just lint wired; cargo fmt --all -- --check and cargo clippy ... -D warnings both run clean.
04 Schema validation at boundaries 🚀 Ship-Ready
Strongly-typed serde sidecar versioned via schema_version with a migrate command policy (CLAUDE.md:106); CLI config typed through the config crate; AnthropicClassifier forces a single tool-use response with a JSON-schema-constrained shape so the LLM can't emit free-form text.
05 Business logic separated from I/O 🚀 Ship-Ready
Textbook hexagonal: paperclaw-domain = pure types + trait ports; paperclaw-app = use-cases; paperclaw-adapters = I/O impls; paperclaw-cli = composition root. Dependency-direction rule stated in CLAUDE.md:19. In-memory fakes provided by paperclaw_domain::testing.
06 One-command bring-up 🚀 Ship-Ready
justfile exposes one verb each: just check (fmt-check + lint + test), just test, just run, just doctor. Every recipe drives --workspace, so the same verbs work uniformly across all four crates with no per-folder special-casing.
07 Pre-commit feedback loop 🩹 Patchy
.githooks/pre-commit exists and runs just check-quick, but git config core.hooksPath is not set in this clone — the hook only fires after a manual just install-hooks. No secret scanning (gitleaks etc.). No test step in the quick loop.
Fix: auto-install hooks on first just run (add a guard to default: that sets core.hooksPath if unset), and add gitleaks protect --staged to .githooks/pre-commit.
08 Dead-code guardrail 👍 Solid
just machete (cargo-machete for unused deps) and just hack are wired, plus pedantic clippy already catches unused code. But neither is in just check or the pre-commit hook — so an agent declaring "check passes" never runs them.
09 Logs reachable from terminal 🚀 Ship-Ready
main.rs:15 initialises tracing_subscriber with stderr writer, PAPERCLAW_LOG env filter, and a PAPERCLAW_LOG_FORMAT=json opt-in for structured logs. CLAUDE.md forbids println!/eprintln! outside tests.
10 Docs stay in sync with code 🩹 Patchy
docs/DESIGN.md exists and CLAUDE.md:22 mandates "update the doc in the same commit", but the rule isn't enforced. CLAUDE.md itself has drifted: lines 170–173 list "OCR, MCP server, search indexing — all stubbed at M2 and built out in M3" while the codebase already ships mcp.rs, ocr.rs, m3_mcp.rs, m3_search.rs, m3_vision_fallback.rs. No hook flags code changes without doc touch.
Fix: add a lefthook-style check in .githooks/pre-commit that warns if files under crates/ changed without a matching docs/ or CLAUDE.md touch, and refresh the "Out of scope" section to reflect M3 reality.
11 Agent can self-test end-to-end 🚀 Ship-Ready
CLI exposes ingest, search, serve-mcp, doctor. Integration tests under crates/paperclaw-cli/tests/ drive the real binary via assert_cmd (cli.rs, m2_ingest.rs, m3_mcp.rs, m3_search.rs, m3_vision_fallback.rs). MCP runs over stdio — an agent can drive it directly. All discoverable from CLAUDE.md.
12 Agentic review panel 💀 Broken
No REVIEW.md. No /review slash command or just review recipe. No CI workflow folder (.github/ is absent). The human is the first reviewer of every diff.
Fix: add a just review recipe that fans out parallel reviewers (e.g. via claude --headless or cargo run -p reviewer) with specialist personas (rust idiom, security, ports-and-adapters discipline, prompt-injection surface) plus a REVIEW.md listing what NOT to flag (theoretical risks, untouched code).
13 Friction proportional to blast radius 💀 Broken
No CODEOWNERS, no danger-zone hook, no extra friction layered on high-blast surfaces. The sidecar schema migration policy is documented in CLAUDE.md:106 but isn't gated; paperclaw-domain/src/sanitize.rs (the prompt-injection seam) and the API-key boundary in adapters can be edited with the same friction as any test fixture.
Fix: add a pre-push hook that git diff origin/main --name-onlys for sanitize.rs, schema version constants, or anthropic*.rs and prints a checklist (bumped schema_version? added migrate path? sanitizer regression test?) with a named bypass like PAPERCLAW_DANGER_OK=1.
14 Tooling tuned for the agent 👍 Solid
Clean signal: clippy lints granular and well-chosen, tests opt out of unwrap_used via attribute (no scattered #[allow] noise), NotImplemented error variants used instead of todo!() so the type system tracks unfinished work. Actionable failure: clippy points at exact spans with cargo fix suggestions. Weaker: the pre-commit hook prints raw just check-quick output without a "run just fmt to fix" hint, and there's no .gitleaksignore-style accept-list because gitleaks isn't wired yet.

🎁 Bonus finds

  • paperclaw doctor subcommand — verifies wiring + env without ingesting anything. An agent can sanity-check the config plumbing before running the real flow.
  • MCP stdio host (serve-mcp) — the binary doubles as a tool surface other agents can drive. Tested in m3_mcp.rs, fully agent-readable.
  • Centralised [workspace.lints] in Cargo.toml — pedantic ratcheted once, every crate inherits. Stops crate-by-crate lint drift cold and makes it impossible to add a new crate that quietly relaxes the rules.
